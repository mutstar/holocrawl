이번 검증은 고정 장비·자동 정책의 전투 코어 비교다. 캠페인 클리어율이나 정상 숭배 UI·저장·신앙 성장·징벌·선물 통합까지 완료한 것이 아니다. 아래 회사 중단/집 실행 중 기록은 역사 자료다.

# 회사 체크포인트 복구와 전투 검증 재개

2026년 10월 19일, 회사에서 저장한 22신 체크포인트를 별도 폴더에 복구했다. 부모 폴더의 기존 16신 기획서는 과거 보존본이다.

## 완료한 확인

- 아카이브의 772개 파일 크기 및 SHA256과 소스 패치 해시 일치.
- DCSS 0.24.0 커밋 `a7d21def0a8b0b39c6825b643a3b51f371b73583`과 4개 의존성 복구.
- 로컬 MSYS2 GCC 16.2.0으로 새 실행 파일 빌드 성공.
- 노엘·소피아 및 신규 20개 전투 모듈의 native fixture 검사 통과.
- 근접·원거리·주문 각 552개, 총 1,656개 정역순 재현 일치.
- 동일 1,656개를 회사 PC의 05 결과와 비교해 모든 기록 일치.
- 승인된 기획 수치와 엔진 소스에는 변경 없음. bootstrap의 저장소별 줄바꿈 설정과 새 실행 감독·진행률 도구만 추가했다.

## 진행 중인 실행

새 버전은 **v3**, 재현 버전은 **home01**이다. 목표는 1,000시드 × 8상황 × 23종류 × 3빌드 = **552,000조우**다. 신 22명과 무신앙 1종을 비교한다.

6개의 컨트롤러가 각각 250시드 샤드 2개를 순차 실행한다. 현재 진행 상태는 `analysis/native/batch/job_state.json`이 기준이다. 회사의 v2 부분 87,137행과 과거 개발 결과는 별도 보존되며 새 최종 데이터에 합치지 않는다.

진행률 확인:

```powershell
./.toolchain/msys64/mingw64/bin/python.exe analysis/home_batch_progress.py --version v3
Get-Content analysis/native/batch/job_state.json -Raw
```

행 수는 진행 표시일 뿐 검증 완료가 아니다. 모든 컨트롤러가 실제 exit code 0으로 끝난 뒤 감독 스크립트가 전체 샤드·동결 해시·시드 완전성·정역순 샘플·기존 노엘/소피아 기준군 대조를 검사한다. 실패 시 부분 결과와 로그를 남기고 최종 완료로 표시하지 않는다.

## 완료 시 확인할 파일

뭇별의 ‘끝까지 돌리고 신별 밸런스 결과를 알려달라’는 요청에 따라, 이 대화에 완료 후속 확인을 설정했다. 자동화 ID는 `22`이며 10분 간격으로 실제 상태를 확인한다. 변화 없는 진행 중에는 알리지 않고, 오류·사용자 조치 필요 또는 최종 결과 때만 알린다. 최종 보고 후 후속 확인을 중지한다.

집계 도구의 화면 출력이 JSON 요약과 같은 경로에 저장되는 문제를 수정했다. 화면 출력은 `.summary.log`, 기계 판독 요약은 Python이 생성하는 `.summary.json`으로 분리했다. 새 PC의 여섯 재현 요약을 다시 생성하고 JSON으로 읽어 552건씩 완전성을 확인했다. 실행 중인 구형 컨트롤러가 생성하는 샤드 요약은 최종 집계 단계에서 수정된 도구로 재생성된다. 전투 소스·바이너리·기획 해시는 변경하지 않았다.

- `analysis/native/batch/job_state.json`: `phase`가 `home-final-validation-complete`, `finalDatasetComplete`가 true.
- `analysis/native/batch/validation.json`: `status`가 passed, `version`이 v3, `encounters`가 552000.
- `analysis/native/batch/RESULTS_ALL_GODS.md`: 22신 비교 보고서.
- `analysis/native/batch/all-gods-summary.json`: 빌드·상황별 승률과 차이, 구간, 효과 집계.

프로세스가 중단되면 해당 샤드를 완성으로 간주하지 않는다. 중간 조우부터 이어쓰는 기능은 없다. 기존 로그와 상태를 먼저 확인하고 새 실행 이름을 사용한다.

## 결과의 범위

고정 장비와 정해진 자동 행동 정책의 실제 엔진 전투 비교다. 일반 플레이의 신 선택·저장·캠페인 신앙 수급·징벌·장비 선물까지 완성했다는 뜻이 아니며, 승률을 던전 클리어율로 해석하지 않는다. 자세한 범위는 `analysis/native/batch/VALIDATION_SCOPE.md`를 따른다.
