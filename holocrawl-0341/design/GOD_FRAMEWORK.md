# 22신 구조 초안 / 0.34.1

사용자 방침: 공통 구조와22신 자리를 먼저 만든 뒤 개별 컨셉·수치·권능을 수정한다.

## 구성

`design/gods0341.json` → 생성 스크립트 → 네이티브 등록표와 브라우저 검토 화면

- 신을 저장하는 식별자는 `suisei` 등의 고정 문자열이다. 목록 순서나 이름을 바꿔도 저장 ID를 같이 바꾸지 않는다.
- 1·3·5성은 기존 권능 참고 자료를 담는다. 액티브/패시브/혼합/표적 지정이 있는 패시브를 구분한다.
- 2·4성은 추가 패시브 검토 자리다. 모든 칸의 채택을 확정한 것은 아니다. 이미 작업한 패시브6개는 기존 내용으로 옮겨뒀다.
- 비비·소피아·메라는 예전 실전 코드보다 나중에 합의한 개편안을 참고한다. 원본 자료는 `redesign-references`에 있다.
- 수치·기도술 조건·비용은 개별 검토 전이다. 신앙30/50/75/100/120은 기존 기준을 가져온 편집 가능한 기본값이다.
- 효과가 미구현인 권능은 실행 성공으로 처리하지 않는다. 호출해도 자원·신앙·쿨다운·턴을 소비하지 않는다.

## 저장 틀

0.34.1의 `CrawlHashTable` 속성 저장 형식을 이용한다. 키는 `holocrawl0341`, 스키마 버전은1이다.

```text
state
 ├ current: 현재 신의 고정 ID
 ├ piety: 공통 신앙
 └ per_god[고정 ID]
     ├ joins / departures: 숭배·배교 횟수
     ├ mode: 전환 형태
     ├ resources: 별·주목·불씨 등 신별 자원 자리
     ├ cooldown_aut: 남은 재사용 대기
     └ duration_aut: 남은 지속시간
```

배교·전환 시 임시 자원·모드·지속시간·쿨다운을 정리하고 이력은 보존하는 공통 동작을 준비했다. 향후 개별 신의 예외 정책과 배교 징벌은 따로 연결한다. 자동 회복·신앙 수급 조건·단별 피해 계산은 아직 없다.

다음 연결 계약은 턴 경과, 자발 이동, 직접 적중, 피해 수신, 경험치 적 처치, 주문 시전, 층 이탈이다. 현재는 연결 지점의 목록이며 실제 전투 이벤트가 호출하는 상태가 아니다.

## 실제 연결 상태

네이티브 실행 파일 안에 등록표·상태 연산·속성 저장 어댑터가 들어갔다. 진단 명령으로 확인할 수 있다. 일반 게임의 제단, 권능 메뉴, `you.props`, 전체 캐릭터 저장·복원 흐름에는 아직 연결하지 않았다.

`-holo-structure`는 편집 원본과 같은 등록표 JSON을 출력한다. `-holo-structure-test`는582개 구조 검사를 수행한다. `-holo-state-write/read`는 원본 속성 직렬화 형식으로 테스트 상태를 저장하고 별도 프로세스에서 읽는다. 이는 전체 캐릭터 세이브 검증이 아니다.

## 검토·빌드

- 구조 화면: `preview/gods/index.html` 또는 `http://127.0.0.1:8797/gods/`
- 등록표 수정: `design/gods0341.json`
- 생성 및 빌드: `BUILD_STRUCTURE.ps1`
- 네이티브 검사: `scripts/validate-structure.py`
- 검증 결과: `analysis/structure01/validation.json`

원본0.34.1 검증 실행 파일은 `runtime/base0341`에 보존한다. 현재 소스는 구조 모듈을 포함하므로 이후 빌드는 `BUILD_STRUCTURE.ps1`을 쓴다. 구조 실행 파일은 `runtime/structure01`에 생성되며 진단 스크립트는 기반 실행 폴더의 DLL을 사용한다.
